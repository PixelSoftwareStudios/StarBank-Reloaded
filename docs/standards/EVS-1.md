# EVS-1 — Engineering verification standard

Every requirement has acceptance evidence and an owning module. Verification proportional to risk, not a checklist of decorative tools. No completed evidence in this design pack; every obligation starts Pending. Design before implementation; test failure path first for irreversible writes.

## Required baseline

- Unit tests, rstest parameterized fixtures, integration and conformance tests; `cargo-nextest` native matrix; rustdoc/doctests; `cargo fmt --all -- --check`, Clippy `-D warnings`, cargo check/test with meaningful supported features and target combinations (not blindly `--all-features` for mutually exclusive native/WASM). `cargo-deny`, `cargo-audit`, npm lock/license/security checks, minimal unsafe review. Frontend Biome, strict tsc, Vitest, Playwright including Chromium/Firefox/WebKit capability fallbacks and Tauri end-to-end native harness (Playwright alone doesn't test native window/filesystem). Native runners for Windows/macOS and Linux supported manual flow; wasm32 check/build and worker integration. No fake green jobs. Collect artifacts/snapshots and logs with sensitive data redacted.
- `proptest` for structural invariants, exact arithmetic, stable ordering, edit/revert and lossless-or-reject properties. `insta` for semantic XML, diagnostics, DTOs, diff and UI golden snapshots (review changes, don't blindly accept). `cargo-fuzz`/libFuzzer for XML, MPQ untrusted bytes, profile parser, paths/context, malformed DTO/patch and bounds. Regression corpus and minimized failures, time/memory budgets. `criterion` (or maintained alternative) for measured parse/sign/index/editor cost, separate actual hardware profiling. `cargo-llvm-cov` coverage and `cargo-mutants` on critical logic; coverage is not proof.
- Differential tests against pinned StarBank v2.0 as behavior oracle (authorized test-only process/fixtures; provenance/license review), real SC2-generated banks and StormLib archive oracle. Golden expected digests independent of new code. Synthetic fixtures explicitly labeled. No uploading real users' maps/banks, handles or private paths. Native/WASM semantic equality, preserve lexical values, source order and unknowns. Record environment/versions/hashes/fixture rights, compare output bytes or explained semantic differences. Test actual game acceptance only in authorized offline/local context. No online fairness/ban claims.

## Selective deeper verification

| Method | Apply where meaningful | Scope / required evidence |
|---|---|---|
| Miri | Pure Rust parsers/model/unsafe-free helpers; unsafe Rust if applicable | Run supported unit tests; FFI/UI/OS calls excluded with reason, no whole-program soundness claim |
| Kani | Bounded byte/offset arithmetic, exact numeric normalization, checked operation invariants, small transaction transitions | Bounds/assumptions explicit; runnable crate-local harness, counterexample resolution |
| Loom / Shuttle | Single commit ownership, revision/event ordering, worker cancellation and stale generation races | Model synchronization separately from actual FS; explore interleavings and schedules; no relying on random sleep tests |
| TLA+ / TLC | Save/backup/restore state machine with crash, conflict, uncertain outcome; multi-view revision protocol if needed | Model safety invariant, model crash cut points, liveness under assumptions; connect transitions to code with tests, record model bounds |
| Lean / Mathlib + hax / Aeneas | Small pure invariants where proof is tractable: order/normalization, transactional patch all-or-none, no invalid outcome transition | Establish formal spec, extract supported Rust subset or prove abstract relation and refine; explicitly record tool limitations. No claim of verifying SHA-1 cryptography, entire XML/MPQ libraries, OS FS, Tauri or browser. Proof artifacts crate-local; evaluate extraction compatibility first. |
| Fault injection / crash harness | Native writer, backup catalog, settings/cache commit | Real child-process interruption after each boundary, short writes, sync failure, lock/share errors, failed verification, reopen/recovery on actual OS/filesystem. Only verified successful states marked committed. |

Keep verification obligations in `docs/verification/VERIFICATION_REGISTER.md`; formal methods mandatory evaluation, deploy narrowly when useful, never pretend a proof models OS behavior it does not. Proof and test jobs publish actual command, input constraints, exit status and evidence path. Every release gate reviewed against pending obligations; report unavailable tests/blockers. Benchmark budgets proposed after measurement and owner review, not invented hard targets.

# EES-1 — Engineering and agent execution standard

Status: mandatory for new authored code; archive excluded. This is the shared Rust standard adapted to StarBank. Safety and compatibility first. A minimal architecture is better than a large number of empty crates.

## Language, repository and formatting

- Rust 1.100.0 target pin, edition 2024, resolver 3, one Cargo workspace and root lockfile. Verify official toolchain availability at bootstrap; if unavailable, report and approve an actual stable pin rather than silently changing it. Set `rust-version`, workspace package/dependencies/lints inheritance. Build `--locked`; commit lockfiles, pin pnpm/node/tool versions and dependencies after compatibility check. Update intentionally, not as side effects. `original/` is frozen and outside new builds/lints. Apps exclusively under `apps/`; reusable code under grouped `crates/` and `packages/`. One low-level `starbank-core` (not `starbank-types`); standalone format library `sc2bank`. Do not introduce empty io/net groups for a local editor; add them only if independently needed. No cycles, minimal public API, dependency graph reviewed.
- Hard tabs in Rust (`hard_tabs = true`, `tab_spaces = 4`), fmt CI. `lib.rs` and every nested `mod.rs` contain only crate/module docs, attrs, declarations, re-exports and structural feature visibility wiring. No types/traits/constants/tests/behavior/algorithm/validation there. `main.rs` initialization only. Maximum 500 authored Rust lines per file by default, responsibility-specific modules; exceptions documented before use, generated/vendor excluded. Rust doc comments for public contract, invariants, errors and safety. No `// NOTE:` comments. Do not change unrelated code/UI. TS strict mode, Biome, consistent Tailwind tokens, semantic HTML, no `any` as escape hatch; Valibot for boundary shapes. Respect language-specific indentation conventions.
- No magic strings or unexplained numbers: enums/newtypes for closed domains, named constants for protocol/format tags, keys, units, limits and repeated literals. One-off UI copy allowed. Preserve unknown on-disk variants. Error types domain-specific (thiserror candidate), contextual error propagation, no panic/unwrap/expect for untrusted input. Avoid `as` truncation; use checked conversion/arithmetic for sizes and offsets, exact numeric lexemes, no floating approximation in signatures. `unsafe` forbidden in pure crates, audited minimal isolated native/FFI only with written safety contract, Miri/sanitizer coverage where appropriate.

## Resource and concurrency policy

Bound input sizes, recursion, expanded data, workers, queues, history/cache. Graceful cancellation/shutdown, backpressure, no unbounded task spawn or busy polling. Pure functions deterministic across locale/platform. Single mutation owner per document/target; explicit revision, stale event rejection. Rayon only for independent CPU-bound work, IO blocking workers separate, no parallel sorting small banks, no unnecessary multi-threading. Avoid allocating redundant bank trees, keep source baseline and edit patches, cache metadata not Galaxy script. Use borrow/stream/reuse as warranted; do not prematurely optimize by sacrificing fidelity. Benchmark cold/warm startup, idle and peak memory, CPU, UI interaction, large bank operations, browser worker/IPC size. No fixed claimed savings without measurements. Tauri webview overhead is real; measure total process tree including helpers on all native platforms, JS heap/WASM memory in browser.

## Dependencies and security

Prefer std and focused mature libraries with clear licenses, maintenance and tested platform support. Check actual source API, deprecation, features, release activity, MSRV, build targets, transitive graph and license. Prefer permissive/Blue Oak compatible where feasible; legal provenance review mandatory. Do not rely on earlier fabricated dependency recommendations. Use the shared Radix primitives and Valibot schemas. The editor runs without a backend server. Scope IPC, local path access, capabilities, archive/ XML parsing bounds; no telemetry or secrets in logs. No game process attachment or execution of untrusted map scripts. Safe storage with typed commit outcomes and conflict checks. Never silently mutate unexpected files.

## Agent workflow

- Inspect real checkout and applicable AGENTS, use requirement ID + scoped plan and acceptance tests before implementation. Report uncertainty/decisions; do not assume upstream behavior without inspected source and permalink/line reference. Do not fabricate evidence or use undocumented APIs. Prefer a narrow spike when an external dependency is uncertain. Keep assumptions and pending evidence explicit.
- Small, atomic Conventional Commits, one behavior/test/doc concern each; meaningful scope, include regression tests. No unauthorized push/force-push, releases, history rewrite, deletion or broad reformat. Stage exact changes; avoid altering approved UI except requested. Preserve unrelated user modifications. Parallel coding agents use disjoint worktrees/branches and ownership contracts; one integrator coordinates shared Cargo/pnpm manifests/DTO/fixtures; integrate and rerun gates. No concurrent modifications to shared invariant implementation without agreement.
- Every completed task reports actual commands/results, failures and missing platforms; never mark proof/tests passed without execution. Test code at least comparable to production code, target ~2:1 on critical parser/signer/commit logic as review signal, never meaningless tests for ratio. Keep production behavior and verification artifacts crate-local (`tests`, `benches`, `fuzz`, `verification`). No global dumping ground. CI enforces formatting, warnings, dependency/lint rules, 500-line/structural rule, test matrix and evidence.

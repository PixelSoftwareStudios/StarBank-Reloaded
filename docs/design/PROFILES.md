# Game profiles and extensibility

Simple View is a genuine game-aware view, not a hand-written form unrelated to the bank. It appears when a bank matches a profile with sufficient confidence. User wants one friendly field to perform all necessary dependent adjustments automatically; raw/table remain available for every supported bank. Profiles are data/logic independent of frontend, shared desktop/web/CLI. Preserve legacy Go `internal/schema/schemas/README.md` format: embedded YAML `map` basename, `groups` labels, `fields` with `label`, `section`, `key`, `type` (`number`, `checkbox`, `string`). Go archive has no actual map schemas; do not invent support for named maps. Provide synthetic fixtures only, migrate compatible schema definitions if discovered.

## Proposed versioned contract

Profile ID, schema version, game/map identifiers (author handle, bank name, optional known map version/fingerprint), match predicates with confidence and required fields, grouped labels/descriptions, typed controls, canonical field paths including child name/occurrence, explicit mappings and validation, dependent edit rules, optional known codec/validation strategy version. Runtime validates imported config (Valibot shape at UI boundary, Rust authority); safe declarative bounded operations with no arbitrary code evaluation/network/FS. Built-in profiles reviewed and tested; optional user profiles later. Ambiguous/mismatched profile prompts choice or falls back to Table. Do not guess based solely on map display name; no collision overwrite. Use exact stable IDs, no missing-key auto-creation unless explicitly in rule. Present preview of all dependent changes and diagnostics; apply as one transaction, all-or-nothing. Rule graph deterministic, reject cycles/overflow, checked exact integer/decimal operations. Undo/revert handles whole transaction; no silent overwriting external changes. Preserve unknown fields and custom data. Profile rules not a duplicate signing algorithm.

## Protection distinction

Standard SC2 bank digest compatibility is core; map-specific checksums, encoded/obfuscated values, multiple dependent fields or custom formats are supported only where documented/authorized/tested. Provide clear status `unsupported/unknown custom validation` rather than promising universally valid edits. User-assisted schema/profile tooling, read-only analysis and format recognition possible stretch. Runtime-bound/server-authoritative protections, live process reading/patching, injection/trainers, account or map ban evasion not part of product; no guarantee of online acceptance or lack of ban. Do not automatically treat every changed checksum as a cheat flag or infer safe-to-edit keys. Support authorized local map inspection/repair separately from bank signing. No arbitrary user script runtime or plugin sandbox required initially.

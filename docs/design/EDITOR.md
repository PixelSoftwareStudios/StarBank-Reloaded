# Editor lifecycle, exact values and transactions

## Single document, three projections

Native Rust owns a revisioned document session, browser Rust/WASM owns an equivalent session. React/Zustand stores projections and transient UI drafts; no competing canonical model. Each request has document ID, expected revision and request ID. Stale responses are ignored; stale mutations are rejected and require explicit reconciliation. Stable section/key/value occurrence IDs, not row indices or names, identify edits through sorting/filtering/virtualization. Do not clone entire banks on every keystroke. Use a baseline immutable source plus sparse history and patches; profile actual costs.

Session tracks opened original bytes/metadata, current committed model, pending raw or field drafts, last successful saved state/fingerprint, dirty differences, selected context, validation and signature state. The **Reset** button restores original opened values without disk I/O; confirmation only when changes would be discarded. Clarify post-save behavior in settings: default original opening snapshot remains recoverable within session; a separate revert-to-last-save action/explicit reopen is available. After successful save clean state refers to last saved bytes, so resetting to an older original can correctly mark dirty. Save As switches current path on success by default, with option to export a copy. Copy XML never changes active path, baseline, on-disk fingerprint or dirty state. Failed save never marks clean. No silently resetting baseline on selection/render.

- `Open`: parse only selected bank; retain exact original bytes, file identity, context and diagnostics; missing signing context permits inspection.
- `Edit`: transaction containing one or many typed operations; validate all before applying; commit all or none; one undo unit. No invisible dependent mutations. Invalid draft visible locally; Save disabled if any relevant draft invalid.
- `Switch`: commit valid drafts or explicitly discard/cancel invalid draft; preserve selection and scroll where relevant. Unsaved file/map/account/settings navigation/close prompt Save / Discard / Cancel (settings navigation itself should keep editor session alive). Background indexing never overrides edits.
- `Raw View`: CodeMirror editor (XML highlighting, monospace, line numbers, selection, undo, find; optional Format XML/Validate XML). Open lazily using actual XML, never placeholder. Keep syntax-invalid drafts without changing last good model. Debounce lightweight syntax checks; authoritative parse on apply/switch/save/export. Valid raw edit becomes atomic replacement transaction with revision and diff. Raw text formatting changes visible and undoable. No network language service. Raw save re-signs via same pipeline by default, not merely `write_text`. Reconcile CodeMirror local undo with document history; avoid double application. If raw author intentionally supplies signature and auto-sign off, preserve it, report verification status. Do not silently discard unknown nodes.
- `Table View`: original Sections sidebar by default, section selection, full-height virtualized table `Name | Type | Value`, editable typed fields; multi-value children identifiable with child label/subrow (do not lose group identity). Alternate unified table includes Section column or group headers. Section search/filter, key name filtering, add/delete section/key/value, rename and type change (validate and confirm where destructive). Display order independent of stored/signing order. Header click sorts if enabled, with small up/down chevron immediately next to Name, not separate sort button; user previously removed misplaced arrow, so do not force sorting UI beyond this accepted placement. Default stable source order unless configured. Case-insensitive display search, no locale collation in signature. Preserve selection by stable IDs when rows recycle.
- `Simple View`: conditional game-specific profiles, names/inputs meaningful to user, grouped fields and correct dependent edits. Default if confident profile; otherwise Table View, Simple tab hidden/disabled with explanation. No generic mock Gold/Level presented as real bank fields. Profile and raw/table always refer to same document. See PROFILES.

## Numeric formatting: mandatory, not stretch

User explicitly requested commas accepted while typing, stripped when writing. Use React Number Format (or validated equivalent) integrated with the shared editor text input. Work in strings end-to-end, never JS `Number`, `parseFloat`, f64 or implicit JSON number for exact bank values. `1,000,000` -> `1000000`; `-1,234.50` -> `-1234.50` for a supported signed decimal field; `1,000` pasted into a numeric field accepted. Display grouped number with commas while editing or on blur; keep caret/selection stable, support backspace/delete/paste, negatives, fractional digits, empty/intermediate input. Reject malformed grouping when committing (`1,,2`, `12,34`), invalid characters, out-of-range, excessive precision, nonnumeric exponent/NaN/Infinity unless proven supported. Do not normalize any arbitrary string/text/point/unit value as a number. Existing Go `NormalizeNumber` removes spaces too: support a deliberately validated grouped-space paste if required, not indiscriminate deletion. Default grouping is ASCII commas and decimal dot, no locale-dependent signing. Preserve sign, zeros and decimal precision when untouched; only normalize intentional numeric edits. Type/range rules from real SC2 format/profile fixtures, not a blanket positive-only 32-bit guess. Unknown types remain lossless text with warning. Booleans/flags preserve observed representation, profile checkboxes may explicitly map to `1`/`0`. Inline messages and red invalid outline, field label/accessibility, no modal on every keystroke. Validate all fields and cross-field invariants in Rust before applying or saving; UI Valibot for draft/schema/IPC shape only.

## Multi-edit and history

Select rows by click/checkbox, Ctrl/Cmd, Shift range; keyboard accessible. Mixed value indicator; shared input applies same typed value to every selected compatible field; preview count and affected values. Validate every target before one atomic transaction. Incompatible selections explain why; do not partial-apply. Bulk same-value is required; arithmetic add/subtract/multiply and presets are optional later and must be checked for overflow/precision and never invent game constraints. Undo/redo, per-key/per-section revert, section dirty dots, global dirty count, original vs current diff (add/remove/change, exact values; optional last-saved/backup comparison). Keep bounded revision history without losing original snapshot. Read-only mode optional. Confirm dirty close and navigation, external file change prompts reload/compare/save copy; never silently overwrite. Raw and structured undo boundaries explicit.

## Acceptance examples

- Load actual multi-value XML -> see each child -> edit one child -> other untouched, switch views and see same change, reset returns original, save/reopen round-trip.
- Numeric draft `1,000,000` updates canonical `1000000`; copy/save/hash use canonical value; string `A, B` retains comma; `9007199254740993` never rounded by JS; invalid draft prevents all writes.
- Multi-select three rows, apply one value, one undo restores all; one invalid row rejects all. Recycled table row never writes to stale selected section.
- Edit invalid Raw XML, navigate to Table View, see explicit repair/discard/cancel choice; nothing on disk changes. Fix XML then save with new signature. Copy includes full current prepared bank XML, not path or cached last-loaded text.

# Native, browser and distribution

One frontend, same engine behavior. Tauri 2 system WebView (WebView2 Windows, WKWebView macOS, WebKitGTK Linux), not Electron or bundled Chromium. Native Rust commands own file operations and document sessions. Browser static Vite build with wasm-bindgen and worker (WASM init lazy); no HTTP API, accounts, server database, uploads, telemetry, cloud sync. Ship all scripts/assets/fonts locally; no CDN dependency for editor. Static Cloudflare Pages candidate; optional offline PWA only after cache update/version consistency design. Do not claim first-visit offline. No Next.js/SSR. Native app works offline.

| Capability | Desktop | Web |
|---|---|---|
| Parse, validate, three views, profiles, sign, diff, undo, copy | native engine | same engine via WASM |
| Auto-detect roots/cache | Windows/macOS; Linux stub | unavailable |
| Open single/multiple external files; drag/drop | native chooser/drop/open events | file input/drop |
| Directory | native chooser | File System Access API when supported; folder-input/import fallback |
| Save overwrite | verified storage on qualified targets | unavailable until a browser writer can enforce expected-content replacement and preserve displaced bytes |
| Save As/copy | native save dialog/clipboard | download for Save As; clipboard with user gesture and permission fallback |
| Backup/restore | managed storage + explicit same-directory backup | download exact opening bytes as a backup |
| Open in Folder, watch, associations | native scoped APIs | disabled with explanation; no fake path reveal |
| MPQ | native reader/writer selected by spike | optional WASM capability only after tests |

Platform abstraction `BankEngine` commands and `FilePlatform` capabilities, not UA sniffing. Rust native / WASM expose same versioned DTOs, exact value strings. Browser engine in worker with bounded queues, transfer ArrayBuffers where supported, cancel/generation handling; avoid duplicate copies. IPC only typed application commands, no arbitrary FS access/shell/network commands. Scope Tauri capabilities to known windows, picker-selected/authorized handles, validated roots; no broad unrestricted filesystem permissions or unsafe remote content. Use safe CSP, avoid remote navigation/scripts and inline unsafe eval, audit npm/Rust deps, escape user XML and filenames as text. Worker/WASM fallback/error state visible. Local path data not sent to any network. Save/clipboard operations honor browser gesture constraints. Store browser settings locally (versioned, no sensitive content by default); native app config/data/cache paths via `directories` or native API, migrate original `StarBank-Reloaded/settings.json` keys `hide_blizzard_maps`, `hide_maps_without_banks`, `auto_resign_on_save`, `sc2_root_override` without losing user choices. Invalid settings are reported and recoverable. Persist layout and last selection optional; no saved raw bank drafts without explicit consent.

Browser Save As downloads the prepared bank. The opening backup downloads the exact bytes read during import. The save picker can truncate an existing destination before returning a handle. Writable streams from an existing handle still lack an atomic expected-content check and displaced-version recovery. These limits keep browser overwrite unavailable. Apply the CSP to the worker script as well as the document. [Browser storage qualification](../verification/BROWSER_WRITES.md) · [Worker CSP](https://html.spec.whatwg.org/multipage/workers.html#run-a-worker)

Desktop Advanced settings can save Auto or a limit of one to four map-index workers. Each new scan or rebuild reads the saved limit. A chosen limit only reduces the existing automatic cap of four workers and half the available CPUs, with at least one worker. Old version-1 preferences without this field retain their other values and use Auto. The browser identifies map indexing as desktop-only.

An unreadable saved-folder record blocks passive discovery until explicit recovery. Canceling or choosing an invalid folder preserves the record. A valid recovery is checked before its scope is published. Recovery refuses a record that another process has already repaired. If the platform cannot resolve an app-config directory, explicit folder selection can authorize the current session with a persistence warning; startup in a later session again requires an explicit choice. Direct bank-file opening stays independent of folder discovery.

## Packaging / associations

Tauri bundle native app/installers; verify actual CLI config and plugin APIs for chosen version. Windows installer registers ProgID / file association `.SC2Bank`, open command quoted correctly, lets OS/user choose default rather than hijack. macOS `.app` document types/UTType declaration, open-file events both cold and running app, codesigning/notarization and DMG distribution as appropriate. Linux `.desktop` Exec file argument, MIME type/extension, desktop/MIME registration via installer/packages (manual bank support initially); package AppImage/deb as evaluated. No file association merely from executable launch or assuming all platforms argv-only. Startup file args and open events handle case-insensitive extension, multiple requests, existing dirty editor prompts, externally supplied context. Browser not default association; optional PWA file handler future only if supported. Test installer/uninstaller leaves user's banks/config backups untouched; no forced defaults. Build native runners Windows x64, macOS arm64/x64 as supported, Linux optional; sign and notarize only with authorized credentials, no release/push without explicit approval. Native builds must not require Go. Add `just` tasks for reproducible fmt/lint/test/build/wasm/dev/package (original `justfile` and Air are historical only). Check Tauri bundler configuration against current docs; do not repeat unverified Fyne packaging API assumptions.

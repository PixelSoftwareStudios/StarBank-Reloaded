# WP-02 bootstrap evidence

## Foundation

Rust 1.100.0 is available. The workspace pins edition 2024, resolver 3, hard tabs, Clippy, rustfmt and the `wasm32-unknown-unknown` target. Local gates used rustup's Cargo and compiler because Homebrew binaries preceded the rustup shims on the host. Release licensing remains open and the workspace crates have publication disabled. [Rust 1.100.0 release](https://blog.rust-lang.org/2026/11/12/Rust-1.100.0/)

`starbank-core` owns checked revisions and canonical decimal transport. On macOS 14.7.2 arm64, formatting, Clippy with warnings denied, Cargo tests, nextest and rustdoc all passed for the bootstrap crate. Its three tests cover values beyond JavaScript's exact integer range, rejection of malformed or overflowing input and counter exhaustion. See the [shared engine boundary](../design/ENGINE_CONTRACT.md) for the larger contract.

The Rust workflow checks source layout and runs Linux, macOS and Windows native jobs plus an explicit list of portable crates for wasm32. The source checker and CI configuration passed local checks, including actionlint, eight native nextest cases and the core wasm32 build. Windows MSVC compile checks ran on macOS. Hosted CI and Windows execution remain pending.

## Frontend bootstrap

`apps/starbank-web` builds the static entry, and `packages/ui` owns the shared empty workspace. The implementation uses React 19.3.1, Vite 8.3.8, TypeScript 7.0.2, Tailwind 4.3.5 and HeroUI 3.2.8. Node 24.22.3 and pnpm 12.23.0 produced a frozen install without release-age exceptions. Biome, typechecks, the Vitest smoke test and the production build passed on macOS arm64. The npm audit reported no known vulnerabilities at moderate severity or above for this lockfile. [Node release](https://nodejs.org/en/blog/release/v24.22.3) · [pnpm release](https://pnpm.io/blog/releases/12.23.0) · [HeroUI release](https://heroui.com/en/docs/react/releases/v3-2-8)

Chromium 159 and Firefox 159 rendered the production shell in Playwright 1.65.1. WebKit 26.5 rendered it with Playwright 1.61.1 after the 1.65.1 driver failed during WebKit page setup on macOS 14. All three successful runs used a nested static URL with an 850×500 dark viewport and a 390×640 light viewport, with no horizontal overflow, page errors or off-origin requests. [WebKit driver issue](https://github.com/microsoft/playwright/issues/42964)

Valibot 1.5.0, Lucide 1.80.0 and the Tauri 2.12 family were checked in a separate dependency spike. The Tauri CLI started on macOS. Native window rendering, the engine bridge and file controls await their owning work packages. [Tauri releases](https://v2.tauri.app/release/)

## Storage decision

Keep destination creation and expected-target replacement distinct. A replace prepares bytes in a private stage, preserves and verifies supported metadata, and checks source identity and content before publication. Retain the displaced original until publication, durability and readback checks succeed. A post-publication mismatch or ambiguous OS error has an uncertain result. Keep both recovery artifacts and require a fresh inspection before retrying. Windows `ReplaceFileW` can preserve documented DACL and stream information, and some failure codes can move or alter files. This still needs tests on real NTFS. [Microsoft ReplaceFileW](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-replacefilew)

## Corpus and provenance

The archived Go suite has XML and SHA-1 examples without SC2 capture provenance. New synthetic format and signing vectors can qualify specific invariants. Authorized real fixtures need a source and permission record, capture environment, expected behavior and a SHA-256 digest. Keep private inputs and their signing context in an isolated local corpus. The [pinned upstream audit](../reference/UPSTREAM.md) records the source reviewed and the remaining licensing questions.

# Browser overwrite qualification

Web Save As and opening-backup export use a local download and leave the dirty checkpoint alone. A picker-selected write grant is available in Chromium, and it grants authority to write. It provides no atomic precondition on the bytes being replaced.

- WICG's save-picker steps can clear an existing selection before the caller receives its handle. The picker is unsuitable for writing a bank whose old bytes must survive failure. [File System Access §3.4](https://wicg.github.io/file-system-access/#api-showsavefilepicker) · [Chromium regression test](https://chromium.googlesource.com/chromium/src/+/b8f90f5ac39d33dabdd5706124ae58e050db8194/content/browser/file_system_access/file_system_chooser_browsertest.cc)
- An existing handle from the open picker avoids the picker truncation. The writable stream stages data until close. Chromium's exclusive mode excludes competing writers behind its browser lock manager. The close path passes the destination URL and preserve-permissions option to a swap move. It has no caller-supplied expected identity or content fingerprint. [File System Standard §2.3.2](https://fs.spec.whatwg.org/#api-filesystemfilehandle-createwritable) · [Chrome exclusive writer documentation](https://developer.chrome.com/blog/new-dev-trial-for-multiple-readers-and-writers/#exclusive-writer-for-filesystemwritablefilestream) · [Chromium lock manager](https://chromium.googlesource.com/chromium/src/+/8fba5b2d/content/browser/file_system_access/file_system_access_lock_manager.cc) · [Chromium writer close](https://chromium.googlesource.com/chromium/src/+/8fba5b2d/content/browser/file_system_access/file_system_access_file_writer_impl.cc#246)
- A last-minute read plus verified readback detects an earlier conflict or a mismatched final state. An external native writer can still replace the bank after the check and before the swap. Verified output would then say nothing about preserving the intervening version. The browser stream exposes no safe displaced-version recovery or native durability receipt. The application therefore leaves overwrite unavailable under its save contract and retains the validated edited-copy and exact opening-backup downloads. This qualification follows API and source inspection.

## Opening backup implementation evidence

On macOS arm64, the isolated dfe70d8 integration with the format and editor UTF-16 overlays passed the full offline browser workflow in Chromium 159.0.8154.6, Firefox 159.0, and WebKit 26.5. The test verified exact source bytes for an edited UTF-8 CRLF bank and a BOM-marked UTF-16LE bank after Table and Raw edits. It also verified UTF-16LE edited recovery after an injected worker failure. The opening backup preserved the dirty state and retained the original byte sequence even when the re-sign option was selected. WebKit used the matching Playwright 1.61.1 fallback locally. App typecheck, the Vite/WASM build, scoped Biome, and all 39 app tests passed.

## File-drop acceptance

On 2026-11-27, the production renderer with the real WASM engine passed file-drop checks in headless Chromium 159.0.8154.6, Firefox 159.0 and WebKit 26.5. Browser-native File and DataTransfer objects entered the actual dragover/drop handlers through synthetic DOM events. A BOM-marked UTF-16LE/CRLF bank opened and downloaded with its exact original bytes and filename. Multiple-file drops and drops over an unapplied Table draft issued no Open command. Cancelling dirty-bank replacement retained the current bank; confirming a malformed replacement also preserved its dirty values. A confirmed valid replacement opened the new bank. Worker instrumentation only counted outgoing Open requests and forwarded them unchanged. These checks cover the event contract, not a physical operating-system drag gesture. [Drop cases](../../apps/starbank-web/test/drop-import.mjs)

The final focused drop cases passed in all three engines. Scoped Biome and the Vite build passed. Local WebKit used the matching Playwright 1.61.1 fallback; hosted execution of this addition remains pending.
